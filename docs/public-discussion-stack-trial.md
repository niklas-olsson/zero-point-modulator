# Installed independent public-discussion trial

This scene checks two independent OpenJules participants using the installed
restricted Polyphony profile over actual loopback Hyperswarm. Alpha proposes a
baseline, Beta declines immediate approval with a specific objection, and Alpha
retains that objection in its follow-up. Each participant must receive the
other's original signed record. Their separate durable histories and original
publication receipts must survive process restart and exact completed-turn
replay.

The provider is an explicit local HTTP fixture that returns three predetermined
responses. It runs no model. The scene establishes transport, attribution,
retention, explicit-turn allowance and passive-observation behavior. It does not
establish a live model's judgment, confined-child discussion, later private
rounds, warm provider reuse, publication-before-journal crash recovery, or an
actual generated forge proposal. Those criteria remain separate in
[ZPM #3](https://github.com/niklas-olsson/zero-point-modulator/issues/3).

## Reuse the actual installation

Run the existing [managed-stack trial](managed-stack-trial.md) successfully
first. Keep its private work directory after its services have stopped. This
scene verifies that report, the sealed bundle, the retained managed selector,
all three source revisions and completed environment markers. It uses the
installed OpenJules and Polyphony interpreters directly. It creates no new stack
bundle, Docker image, enrollment, canonical task, authority connection or child
runtime.

Install the selected Polyphony sidecar's locked dependencies with `npm ci`.
Node must actually be executable through `/usr/local/bin:/usr/bin:/bin`, the
restricted profile's fixed PATH. An ambient `setup-node` PATH alone is not proof
of that prerequisite. Linux with `/proc`, child subreaping and `waitid(WNOWAIT)`
is required. An enabled trial fails if a prerequisite is missing.
Both installed discussion interpreters must resolve the qualified MCP 1.30.0.

```sh
cd /absolute/checkouts/polyphony/src/liminal_bridge/sidecar
npm ci
cd /absolute/checkouts/zero-point-modulator
python tests/contracts/check_public_discussion_stack.py \
  --managed-stack-dir /private/managed-stack-trial \
  --work-dir /private/public-discussion-trial
```

The discussion directory must be new and outside the existing installation.
It retains private scope material, two A configurations, separate A identity
stores, separate B journals, immutable explicit turn files and raw command logs.
Neither participant receives the managed stack's owner or runtime credentials.
The single native loopback bootstrap endpoint remains live throughout this
scene. Restarting that bootstrap is not part of the evidence.

## Required observations

Initialization and passive observation must produce no provider calls. The
actual `observe` result supplies the full public profile status and history;
local participant status is only a journal/allowance observation.

Each explicit turn reserves 128 output tokens. Alpha has two calls and a total
allowance of 256; Beta has one call and 128. The fixture accepts exactly three
requests and verifies the selected original public context and persona. These
are local allowance units, not a claim about actual billed tokens.

After each turn exits, the source reopens for a natural 30-second passive watch
while the other participant observes from its own latest validated cursor.
Native backfill must deliver the exact original signature, ID, author, timestamp,
content and reply relationship. The source must stop and reap its profile before
another command opens that identity's state. No history is copied between
stores, and no missing delivery triggers another provider call.

Turn `context_after` is explicitly zero in this bounded three-record scene so
that selected historical IDs remain available. Delivery observers have separate
advancing cursors; they never silently reset after a gap. The original turn
files retain their 120-second expiries. Completed-turn replay is a local retained
result and does not require renewing an expired turn.

Both final histories must contain the three original records. Exact replay and
local receipt reads must preserve the recorded results, Alpha's two reservations
and Beta's one reservation, with no fourth request or additional record. The
sealed installation and stopped protected state hashes must remain unchanged.

## Process and time bounds

One 300-second action budget covers all normal operations, including shutdown.
Each B invocation has an outer 55-second limit clipped to the remaining budget;
the component's own startup, observation, turn and cleanup deadlines remain in
force. A failure or expired action budget closes admission and starts one
additional 15-second final containment allowance shared by every remaining owned
process and the provider fixture. The report records action and final cleanup
time separately.

Only the dedicated trial CLI enables verified Linux subreaping. Importing the
module and running the unit-test host do not do so. B deliberately starts A in a
separate process group, so killing B's group alone cannot establish cleanup.
The trial stops owned B producers first, then discovers direct or adopted kernel
children through a bounded read-only PPID inventory. It retains waitable
identities until final signals and reaping. It never signals an unrelated PID
or an unowned nested group. Normal success also requires observed A/Node
relationships and their disappearance after the real participant shuts down.

A descendant may be reaped between its command-line sample and a subsequent
environment or executable read. A missing file is ignored only when a fresh
kernel process lookup also finds no such PID. That sample adds no observation,
readiness, signal authority or cleanup evidence. Existing observations and
deadlines remain unchanged; positive readiness and final owned-process reaping
are still required separately. A live PID, an unreadable fresh lookup or another
observation failure retains the original error and a bounded operation/errno
diagnostic. A permission denial has its separate, stricter existing check for a
previously verified task with unchanged identity and the kernel's exiting flag.

The dedicated unit controls exercise an early-exited parent with a separate
session child, an already expired action budget, failures immediately after
spawn or during ownership inspection, and a normal command alongside unrelated
process work. They are process and provenance fixtures, not installed native
evidence. Missing ownership metadata remains a cleanup failure even when a
still-held child's individual termination can be established safely.
Additional Linux controls force an actual child exit and reap between metadata
reads, both before and after its observation is retained, and check that a
missing-file error against a live or unreadable task remains a failure.

## Evidence and interpretation

Upload only `report.json` or `diagnostics.json`. Raw logs, scope/configuration,
SQLite journals and credentials stay private. The bounded report records exact
component commits and trees, resolved interpreter/MCP/Node/native versions,
the sidecar lock digest, public identities and streams, original signed records
and receipts, selected-context digests, fixture request counts, protected-state
hash agreement, post-replay retained allowance/limits, owned-process
observations and confirmed cleanup. Failure output includes only known command
labels, actual exit codes and bounded process metadata, never raw stderr or
private configuration.

A completed local publication receipt says that the profile stored and
submitted the record. Separate receipt of that original signed record by the
other participant establishes native delivery in this scene. An unavailable
peer, missing record, changed retained identity or unconfirmed process cleanup
fails the trial and retains completed observations without upgrading them into
a passed integrated baseline.
